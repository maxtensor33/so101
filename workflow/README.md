# workflow — 开发流程工件

本目录存放**开发流程工件**（非运行时代码），与 `libs/` `src/` `scripts/`（运行时）
分离。`.claude/` 为本地 AI 工作区配置，不入库。

## 目录

| 子目录 | 内容 | 生命周期 |
|---|---|---|
| `plan/` | 各方向原始计划（`<方向>.md`；`mtc_bk.md` 为归档备份） | 方向启动时写，实施中修订 |
| `tdd/` | TDD 证据报告（`<方向>[.变体].tdd.md`：任务→测试→RED/GREEN 映射、规格表、缺口） | 方向收尾时写 |
| `reports/` | 验收报告（端到端数据、与计划偏差） | 方向收尾时写 |
| `learn/` | 经验复盘（收获 / 踩坑 / "重来一次"改进清单），注明执行的模型 | 方向收尾时写 |
| `problems/` | 跨会话调试交接（卡点、已排除项、根因线索）——**接手新方向必读** | 遇到未解问题时写 |
| `todo/` | 暂停待办（`<域>_<主题>_todo.md`：产物清单、遗留缺口、恢复条件） | 功能暂停时写 |
| `reviews/` | 评审记录 | 按需 |

## 开发偏好与约定（维护者工作流）

### 方向驱动

- 项目按**研究方向**划分（robotics / mtc / envs / rl / il_sim / il_real），
  每个方向独立成体系：计划、测试、报告、文档页、ROS/gym 包命名互不干扰。
- 方向命名贯穿所有工件：`plan/<方向>.md`、`tests/test_<方向>_*.py`、
  `scripts/<方向>_<功能>.py`、`todo/<方向>_<主题>_todo.md`、`docs/<方向>/index.md`。

### 文档先行且必须与实际同步

- 新方向先写 `plan/`（需求重述 / 环境事实 / 实施阶段 / 风险 / 验收清单），
  **等确认后再动代码**。
- 实现落地后同步更新 `README.md`、`docs/<方向>/index.md`、`CLAUDE.md`——
  文档与实际状态不符视为未完成（方向顺序、功能特性、项目结构都要对上）。

### TDD 强制

- 测试先行，先看 RED 再写实现；证据写入 `workflow/tdd/`（任务→测试→
  RED/GREEN 映射 + 规格表 + 覆盖缺口），不省略。
- C++ 侧以编译级测试 + 端到端冒烟为主（沿用现有约定，无 gtest）。

### commit 纪律

- **所有 commit 必须先征得维护者同意**，批准后由 AI 执行或维护者手动执行。
- 功能在独立分支开发 → 批准 commit → merge 回 `main` → 切回 `main`。

### 复盘文化

- 每个方向收尾写 `learn/<方向>.md`：收获、踩过的坑（按代价排序）、
  "重来一次"改进清单——对下一次实施和后续方向都有用。

### 历史坑先读，深水区不死磕

- 接手/新开方向**先通读** `problems/` 与相关 `learn/`：已判死的路线列进
  计划风险表，不再重试（MTC 标准 stage 链即为例证）。
- 遇到"计划外卡点"（30 分钟无进展）立即向维护者汇报卡点 + 已排除项 +
  候选路线，由维护者决策，不闷头重试。

### 验收分工

- headless 可验证的（测试、话题探针、进程状态、error_code）由 AI 完成；
  GUI 画面 / 交互类验收（RViz 显示、遥操手感）由维护者实测，AI 负责把
  验证链路推到"只差人眼"的程度。

### 语言约定

- 交流、注释、文档用中文；代码标识符、第三方工具固定格式保持英文。
